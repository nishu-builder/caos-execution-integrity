Notes on Caos and agent safety

Caos makes an agent's work easier to name, retain, and inspect. A tool, its inputs, and its result can be represented as Git objects, so another person can examine the same bytes. That is useful for safety work, but it leaves important questions about who controls execution, which effects are observed, and what a recorded result actually establishes.

These small experiments make some of those questions concrete. Each uses real Caos jobs and deliberately limited fixtures. The attacks are fixed scripts, so the results tell us about particular boundaries rather than an adaptive model's chance of breaking them.

The examples below show both improvements and their limits. All effects are local fixtures; the private-data example uses an explicitly fake canary.

You can also rerun 32 of the worker jobs from the published Git objects. The package includes the complete worker image and inputs. A small script submits fresh requests to your Caos server and compares the returned trees with the results below. The live services and surrounding policies still need the full demo runner.
